# PRD — 2D 실시간 생존 PvP (V1)

## 한 줄 정의

브라우저에서 플레이하는 **모바일 우선 실시간 2D PvP 생존 게임**. 플레이어는 방을
이동하며 아이템을 획득하고 다른 플레이어와 전투한다. 사망하면 게임이 종료되고
획득 점수를 기록한다.

## 핵심 컨셉

> **"한 칸씩 이동하고, 보이는 정보만으로 상대의 행동을 추론하는 실시간 생존 게임"**

ASCII에서 영감을 받은 텍스트 기반 UI를 쓰되, 구현은 `<pre>`가 아니라 **CSS Grid
기반 고정 격자**다.

---

## V1 목표

가장 중요한 목표는 **AWS 환경에서 실제 다중 사용자가 동시 접속할 수 있는 실시간
게임 서버를 구축하는 것**이다. 그래픽이나 콘텐츠 양보다 다음을 우선한다.

1. 실시간 플레이어 이동
2. 실시간 상태 동기화
3. 전투
4. 아이템 상호작용
5. 방 이동
6. 플레이어 사망
7. 게임 결과 저장

최종 검증 질문:

> **"두 개 이상의 브라우저가 동일한 게임 세계를 실시간으로 공유하고, 서버가 모든
> 게임 판정을 담당하는가?"**

---

## 세션 모델 — 지속형 월드

**라운드, 승자, 자기장이 없다.**

```
접속 -> 방 배치 -> 탐험/전투 -> 사망 -> 점수 저장 -> 재시작
```

방은 서버 메모리에만 존재하며 DB에 저장하지 않는다. 방 수는 플레이어 수에
비례한다(할로 규칙, `GAME_RULES.md` §3).

이 프로젝트는 배틀로얄식 라운드제가 **아니다.** 레포 이름과 무관하게 지속형
월드다. 이 결정을 되돌리지 않는다.

### 원래 초안에서 뒤집은 것

| 초안 | V1 확정 |
|---|---|
| "FOV/시야 제한 제외", "방 전체를 항상 볼 수 있다" | **부시는 예외.** 단방향 가시성을 가진다 |
| "캐비닛 내부에서는 직접 공격할 수 없다" | **블라인드 공격으로 피격 가능.** 대신 마커가 사라지고 총알을 막는다 |

| 방 이동 +10, 아이템 +5 (무제한) | 최초 방문 + 30초 rate cap, 인스턴스 ID 게이트 |

## 시야 정책

방에 들어오면 **방 전체가 보인다.** 단 부시는 예외다.

**공개** — 방 구조, 다른 플레이어 위치/방향, 아이템, 캐비닛, 장애물, 문
**비공개** — 상대 HP, 상대 아이템, 상대 탄약, 상대 쿨다운, 상대의 다음 행동,
캐비닛 점유 여부, 부시 안의 플레이어

상대가 총을 들고 있어도 화면에는 `▲`로만 표시된다. **총을 쏘는 순간에야** 상대가
총을 가졌다는 것을 알 수 있다. 이것이 게임의 핵심이다.

## 완료 조건

브라우저 2개에서 다음이 통과하면 V1 핵심 기능 완료로 정의한다.

1. 브라우저 A 접속 (아이디 입력 + 시작)
2. 브라우저 B 접속
3. 같은 방에 배치
4. A가 이동 → B 화면에서 확인
5. B가 이동 → A 화면에서 확인
6. A가 아이템 획득
7. A가 B 근처에서 공격 → 서버 판정 → B HP 감소
8. B 사망 → B 게임 종료 → A 점수 증가 → 결과 저장
9. 새로운 방 이동 → 기존 방 플레이어 수 변화 확인
10. A가 부시에 진입 → B 화면에서 사라짐 → A는 B를 계속 봄
11. A가 캐비닛에 진입 → B 화면에서 사라짐 → B가 캐비닛 공격 시 A 피격

자동화는 `e2e/two-player.spec.ts`에 있다.
